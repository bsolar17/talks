# git Survival Kit

**Getting out of trouble, and back to a state you trust**

---

## Why a Survival Kit?

- Most git trouble is not lost work, it's **not knowing where you are**
- git almost never throws away a commit: it just stops showing it to you
- A few habits and commands get you back to a **known good state**
- Locally, the main tool is **rebase**: it keeps your branch a clean line of
  commits on top of upstream, and lets you fix them before anyone sees them
- Every scenario in this talk is a demo you can replay on your own machine

---

## Try It Yourself

The demo repos are generated by [`demo.sh`](demo.sh), next to these slides:
only git and a POSIX shell needed.

```sh
sh demo.sh ~/demo               # one repo per scenario, in a new directory
export GIT_CONFIG_GLOBAL=~/demo/gitconfig  # a neutral config, see below
cd ~/demo/graph
```

- Each repo stops **one step before the trouble**: you run the command that
  causes it, then get out again
- `GIT_CONFIG_GLOBAL` hides your own settings, so you see git's defaults; your
  `git config --global` changes go to that file only
- Broke a repo while trying? Generate it again into a new directory:
  `sh demo.sh ~/demo2 graph`

# 1. See Where You Are

---

## `git status` Tells You More Than You Think

- The current branch, and how far it is **ahead/behind** its upstream
- Whether a rebase, merge, cherry-pick… is **in progress**
- How to go on, and how to **get out**: it prints the commands

```text
You are currently rebasing branch 'feature/currency' on '538ffe3'.
  (fix conflicts and then run "git rebase --continue")
  (use "git rebase --skip" to skip this patch)
  (use "git rebase --abort" to check out the original branch)
```

- `git status -sb`: the short version, `## master...origin/master [ahead 1]`

**Read it before and after every command that changes something.**

---

## Demo: The Whole Picture (`graph`)

```sh
git log --oneline         # only the history of the current branch
git fetch                 # update origin/*: what others pushed
git log --graph --oneline --all
```

```text
*   69f0f6c (origin/master, origin/HEAD) Merge pull request #2 from alice/...
|\
| * ead89e7 Reject negative totals
|/
| * 458d673 (HEAD -> feature/refund) Log refunds to stderr
| * b873e2b Add refund
|/
*   4f6ff6c (tag: v1.0, master) Merge pull request #1 from alice/feature/...
|\
| * 9564840 Add discounts
|/
* 74305da Add payment
```

- `--graph`: parents as lines; `--oneline`: one line per commit; `--all`: every
  branch, tag and `origin/*`
- My branch started from `v1.0`; since then a pull request was merged

---

## Demo: Catching Up (`graph`)

```sh
git rebase origin/master  # replay my commits on top of the new upstream
git log --graph --oneline --all
```

```text
* 8a580e7 (HEAD -> feature/refund) Log refunds to stderr
* c363ef0 Add refund
*   69f0f6c (origin/master, origin/HEAD) Merge pull request #2 from alice/...
```

- Rebase **copies** my commits onto `origin/master`: new commits, new IDs; the
  old ones are still in the reflog
- My branch is a straight line on top of upstream again: easy to read, review
  and merge later
- `git merge origin/master` works too, if you prefer: it keeps my commits and
  adds a merge commit; merges into `master` happen in pull requests

---

## Make It a Habit

```sh
git config --global alias.lg 'log --graph --oneline --all'
git lg
git lg -20                # the last 20 commits
git log --graph --oneline master origin/master   # just these two branches
```

- Alias options come first: `git lg <more options>` adds to them
- Run it **before** a risky operation, and **after**: compare the two
- Lost in a long history? `--first-parent` follows the main line only

# 2. Stop Before It Gets Worse

---

## Every Operation Has an Exit

| In progress | Give up, back to where you were |
|---|---|
| rebase | `git rebase --abort` |
| merge | `git merge --abort` |
| cherry-pick, revert | `git cherry-pick --abort`, `git revert --abort` |

- Stuck halfway with conflicts? **Abort is always an option**: back to the
  state before you started
- `ORIG_HEAD`: where the branch was before the last rebase, reset or merge;
  undoes them **after** they're done: `git reset --hard ORIG_HEAD`
- **Branching is cheap**: `git branch backup/currency` before anything risky
  costs a few bytes, and keeps the old state visible in `git lg`

---

## Demo: A Conflict, and the Way Back (`conflict`)

```sh
git status                    # on feature/currency, working tree clean
git branch backup/currency    # just a name for the current commit
git rebase master
# CONFLICT (content): Merge conflict in src/Invoice.java
# error: could not apply 2ac3427... Show currency in totals
git status                    # "You are currently rebasing", and the way out:
#   (use "git rebase --abort" to check out the original branch)
git rebase --abort            # back to before the rebase
git status -sb                # ## feature/currency
```

- `git branch NAME` creates a branch, but **stays** on the current one; unlike
  `git switch -c`
- The backup isn't needed here, `--abort` was enough; it is when a rebase is
  done and you don't like the result

# 3. Understand the Conflict

---

## Three Versions of Every Conflict

- A rebase replays my commits one by one on top of upstream: each one is a
  small merge, and can conflict
- git compares both sides with their **base**; changed on one side only:
  taken; changed on both, in the same place: a **conflict**
- During a rebase:
  - *ours* (`HEAD`): upstream, plus my commits replayed so far
  - *theirs*: **my** commit being replayed
  - *base*: the parent of my commit
- In a merge it's the other way round: *ours* is the branch you're on
- Merge tools show four panes: the three versions plus the result
  (`LOCAL`, `BASE`, `REMOTE`, `MERGED`)

---

## Default Markers: Who Changed What?

```java
    public String formatTotal() {
<<<<<<< HEAD
        return String.format("%d.%02d", totalCents / 100, totalCents % 100);
=======
        return String.format("CHF %d.%02d", cents / 100, cents % 100);
>>>>>>> 2ac3427 (Show currency in totals)
    }
```

- Two versions of the line, but **not the original**
- Did master rename `cents` or did I? Did I add `CHF` or did master remove
  it?
- You can only tell by reading both histories

---

## `zdiff3`: Show the Base Too

```java
    public String formatTotal() {
<<<<<<< HEAD
        return String.format("%d.%02d", totalCents / 100, totalCents % 100);
||||||| parent of 2ac3427 (Show currency in totals)
        return String.format("%d.%02d", cents / 100, cents % 100);
=======
        return String.format("CHF %d.%02d", cents / 100, cents % 100);
>>>>>>> 2ac3427 (Show currency in totals)
    }
```

- Now it's clear: master renamed `cents` to `totalCents`, I added `CHF`
- The resolution keeps **both** changes:
  `String.format("CHF %d.%02d", totalCents / 100, totalCents % 100)`
- `zdiff3` is `diff3` with the lines common to all sides moved out of the
  markers

---

## Demo: Resolving with the Base (`conflict`)

```sh
git config --global merge.conflictStyle zdiff3   # also used by rebase
git rebase master                 # the same conflict, now with the base
# edit src/Invoice.java: keep CHF and totalCents, remove the markers
git add src/Invoice.java          # marks the conflict as resolved
git rebase --continue             # commits it, replays my other 2 commits
git lg
```

- Already in a conflict? `git checkout --conflict=zdiff3 src/Invoice.java`
  rewrites the file with fresh markers in that style
- Also handy when an edit of the markers went wrong: back to the start, as
  long as you haven't run `git add`
- `git rebase --continue` opens the editor for the commit message: save to
  keep it
- `git mergetool` opens a merge tool, usually with the four panes

# 4. Back to a Known Good State

---

## What `git reset` Moves

`git reset <commit>` moves the **current branch** to `<commit>`; the mode
says what happens to your files.

| Mode | Index (staged) | Working tree | Use it to |
|---|---|---|---|
| `--soft` | kept | kept | redo the last commits |
| `--mixed` (default) | reset | kept | unstage, redo commits |
| `--hard` | reset | **reset** | throw everything away |
| `--keep` | reset | local changes kept | move away, keep local work |

- `--hard` discards uncommitted changes **for good**: the reflog can't help
- `--keep` refuses to run if a file you changed differs between `HEAD` and
  `<commit>`: it never loses local changes
- Untracked files are never touched by reset: `git clean -n` lists them,
  `git clean -f` deletes them

```sh
# Committed on master by mistake, with work in progress:
git branch feature/refund          # keep the commit on a new branch
git reset --keep origin/master     # master back; uncommitted changes stay
```

---

## Demo: A Rebase Gone Wrong (`mess`)

```sh
git rebase master          # replays my 3 commits on master
# CONFLICT (content): Merge conflict in src/Invoice.java
git checkout --theirs src/Invoice.java   # "keep my version"
git add src/Invoice.java
git rebase --continue      # git asks for the commit message, then goes on
# Successfully rebased and updated refs/heads/feature/currency.
git grep totalCents        # nothing: master's rename is gone
```

- During a rebase, `--theirs` is **my** commit: master's rename was dropped
- Picking a whole side always throws away the other one
- git sees no problem: the conflict was "resolved"

---

## Demo: What Happened, and the Way Back (`mess`)

```sh
git reflog -6              # every step of the rebase, newest first
```

```text
8c8ddac HEAD@{0}: rebase (finish): returning to refs/heads/feature/currency
8c8ddac HEAD@{1}: rebase (pick): Log refunds to stderr
2a27424 HEAD@{2}: rebase (pick): Add refund
c0b40d1 HEAD@{3}: rebase (continue): Show currency in totals
538ffe3 HEAD@{4}: rebase (start): checkout master
1b6ec2a HEAD@{5}: checkout: moving from master to feature/currency
```

```sh
git reset --hard ORIG_HEAD # 1b6ec2a: the branch before the rebase
git lg                     # as before: try again, with zdiff3 this time
```

- The commits made by the rebase get new IDs on every run; `1b6ec2a`,
  `538ffe3` are always the same
- `feature/currency@{1}`, the branch's previous position, works too

# 5. Fix Your Commits: Interactive Rebase

---

## `git rebase --interactive`

Opens your editor with a **todo list**: one line per commit, oldest first.
Edit it, save, and git replays the commits as told.

| Command | Does |
|---|---|
| `pick` | keep the commit as it is |
| `reword` | keep it, edit its message |
| `edit` | stop after it: amend it, split it, … |
| `squash`, `fixup` | meld it into the commit above; `fixup` drops its message |
| `drop` (or delete the line) | remove the commit |

- Moving lines **reorders** the commits
- For commits nobody else has yet: rebase creates new commits
- Something went wrong? `git rebase --abort` while it runs,
  `git reset --hard ORIG_HEAD` once it's done

---

## Demo: Review Before Pushing (`rebase-i`)

```sh
git log --oneline master..   # my commits, not on master: newest first
# 22dbb6b Add refund test
# c9fd736 Debug charges        <- must not be shared
# 5438892 Add refund           <- has a typo: "Refnding"
git log -p master..          # the same, with the changes
# fix the typo in src/Payment.java
git commit --fixup=5438892 src/Payment.java
# [feature/refund 5237ee3] fixup! Add refund
```

- `master..` means "reachable from `HEAD`, not from `master`": my branch only
- `--fixup=COMMIT` makes a commit `fixup! <its message>`: a note to meld it
  into `COMMIT` later

---

## Demo: Rewriting the Branch (`rebase-i`)

```sh
git rebase --interactive --autosquash master
```

```text
pick 5438892 # Add refund
fixup 5237ee3 # fixup! Add refund
drop c9fd736 # Debug charges
pick 22dbb6b # Add refund test
```

```sh
git log --oneline master..   # 2 commits: Add refund, Add refund test
git diff ORIG_HEAD           # only the debug line is gone
```

- `--autosquash` moves `fixup!` commits under their target, already marked
  `fixup`; I only changed `pick` to `drop` for the debug commit
- `git diff ORIG_HEAD` compares with before the rebase: check that only what
  you meant changed

# 6. The Reflog: Nothing Is Lost (Yet)

---

## The Reflog

- A local diary: every time `HEAD` or a branch moves, git notes **where it
  was** and **why**
- `git reflog`: the moves of `HEAD`, newest first; `git reflog BRANCH`: those
  of one branch
- `HEAD@{2}`: where `HEAD` was 2 moves ago; `master@{1}`: `master` before its
  last move
- `git log --reflog --graph --oneline`: every commit still in the reflog, in
  the graph
- Only on your machine, not pushed; entries expire after 30–90 days
- It records commits, not uncommitted changes: **commit early**, even "WIP",
  and clean up later with `rebase -i`

---

## Demo: Losing Commits (`reflog`)

```sh
git switch master            # leaving feature/export, never merged
git branch -d feature/export
# error: the branch 'feature/export' is not fully merged
git branch -D feature/export # -D: delete anyway
# Deleted branch feature/export (was 112a93c).
git fetch
git status -sb               # ## master...origin/master [ahead 2, behind 1]
git reset --hard origin/master   # "just get up to date"
```

- `-d` only deletes branches already merged; `-D` doesn't check
- `branch -D` prints the commit ID: copy it, it's the quickest way back
- `reset --hard origin/master` threw away my 2 unpushed commits on `master`

---

## Demo: Getting Them Back (`reflog`)

```sh
git reflog -4
```

```text
6cb4a7a HEAD@{0}: reset: moving to origin/master
c986eaf HEAD@{1}: checkout: moving from feature/export to master
112a93c HEAD@{2}: commit: Export invoices as CSV
0e745b2 HEAD@{3}: commit: Add export
```

```sh
git branch feature/export 112a93c  # the deleted branch, back
git reset --hard HEAD@{1}          # master before the reset
git lg                             # everything is there again
```

- The reflog names the command that caused the trouble: `reset: moving to
  origin/master`
- What I wanted was `git rebase origin/master`: keep my commits, on top of
  the new ones

# 7. Configure git to Protect You

---

## Demo: A Surprising `pull` (`pull`)

```sh
git pull
# fatal: Need to specify how to reconcile divergent branches.
git config --global pull.rebase false  # the hint's first suggestion: merge
git pull                     # a merge commit, without asking
git reflog -1                # HEAD@{0}: pull: Merge made by the 'ort' strategy.
git reset --hard ORIG_HEAD   # undone
git config --global --unset pull.rebase
git config --global pull.ff only
git pull
# fatal: Not possible to fast-forward, aborting.
git rebase origin/master     # my decision: my commit on top of upstream
```

- Without configuration, `pull` on diverged branches refuses and asks how to
  go on; the first suggestion makes it merge silently from then on
- `pull.ff only`: `pull` only fast-forwards; when the branches diverged, it
  stops and **you** decide

---

## A Protective Config

```sh
# pull never merges or rebases on its own
git config --global pull.ff only
# conflicts show the base, in rebases and merges
git config --global merge.conflictStyle zdiff3
# rebase -i always moves fixup! commits into place
git config --global rebase.autoSquash true
# fetch removes origin/* branches deleted on the remote
git config --global fetch.prune true
# the whole picture, in two letters
git config --global alias.lg 'log --graph --oneline --all'
```

- Your config lives in `~/.gitconfig`: `git config --global --list` shows it
- Prefer `pull` to always rebase? `pull.rebase true` instead of `pull.ff only`
- Your IDE may run git with its own options: check its settings too

# 8. Graphical Tools

## The Same Moves in IntelliJ

| Command line | IntelliJ IDEA (Git tool window, Log tab) |
|---|---|
| `git lg` | the Log tab: every branch, with the graph |
| `git branch NAME COMMIT` | right-click a commit: **New Branch…** |
| `git reset --MODE COMMIT` | **Reset Current Branch to Here…**: Soft, Mixed, Hard, Keep |
| `git rebase -i COMMIT^` | **Interactively Rebase from Here…** |
| `fixup`, `drop` | **Fixup or Squash Into…**, **Drop Commit** |
| `--abort`, `--continue` | **Abort**, **Continue** in the VCS widget |
| `git reflog` | use the terminal |

- Same concepts, different words: once you know the command, the menu item
  isn't a mystery
- Not git, but a safety net too: **Local History** keeps recent versions of
  your files, also uncommitted ones

---

## Other Graphical Tools

- `gitk --all`: comes with git, shows the graph, nothing fancy
- `git gui`: comes with git, for staging and committing
- [tig](https://jonas.github.io/tig/),
  [lazygit](https://github.com/jesseduffield/lazygit): in the terminal
- Whatever the tool: look for a **graph of all branches** and a way to see
  the **commands** it runs

---

## Takeaways

- **Look first**: `git status`, `git lg`, before and after
- **Abort** what's in progress; `ORIG_HEAD` undoes what's done
- **Branches are cheap**: a backup branch before anything risky
- **Rebase** to catch up; **`zdiff3`** to understand a conflict before
  resolving it
- **`rebase -i`** fixes your commits before anyone sees them
- **`reset --keep`** over `--hard` when you have local changes
- **The reflog**: commits are almost never lost, just unreferenced
- **Configure** git so it doesn't surprise you: `pull.ff only`
